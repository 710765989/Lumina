# M2 .4.8.3 拖出原文件小补丁

日期：2026-10-20。基于 .4.8.2，数据库schema仍为8；桌面设计书保持0.8.1。

从图库媒体卡片拖向外部应用：单张照片或视频直接拖出；拖动选中项带出整个选区，拖动未选项改为该项。默认表达复制，交付原文件路径，不改写、移动原件，不改变标签和相册关系。支持默认、时间、瀑布、列表四种视图，以及相册、标签关联媒体、隐藏内容页；回收站不提供普通文件拖出。

本次修复：

- 禁用缩略图、动图和视频子元素自己的浏览器拖动，避免拖出缩略图URL而非原件。
- 统一卡片拖动逻辑，保留多选，阻止结束拖动时的附带点击误改选区；下一次主动点击正常响应。
- 以稳定媒体ID查询全部原件，去重并保留选择顺序；一次最多10000项。启动前检查文件存在、可读及范围可见性，部分失效时整次阻止，不静默漏掉文件。
- 隐藏内容页显式允许拖出隐藏原件；普通浏览、停用目录和回收站的状态限制保持有效。
- 使用可见的32px拖动图标；主进程与渲染器均防重复准备，失败后释放锁并显示可读提示。
- 不把原生拖动接口返回当作接收端已完成复制；接收端取消不报虚假的成功提示。

验证：工程与React渲染器严格类型检查、生产构建通过，164项自动测试通过。开发构建和冻结EXE各通过13项隔离拖拽检查，包括四视图、Ctrl多选、单视频、中文/空格路径、重复触发、失败后重试、相册/标签/隐藏范围、回收站禁用及原件丢失。冻结EXE另通过4项选择回归：编辑开关与Shift点击、Shift方向键、空白框选及目录启停。

边界：上述窗口验收拦截原生startDrag，以核对真正渲染事件到原生桥接的文件列表和图标；不冒充真实Windows接收。另备独立进程原生接收验收脚本，但桌面控制授权超时，未执行真实鼠标拖放，测试窗口已自动退出。资源管理器、微信和编辑软件实际接收仍待兼容验收。用户本次要求先完成拖拽，虚拟机验收暂缓。
