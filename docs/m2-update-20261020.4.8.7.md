# M2 .4.8.7 启动反馈、缓存任务与设置间距

日期：2026-10-20。基于.4.8.6；设计0.8.1、schema8不升版。

- 启动先显示400×250的蓝白加载小窗，主窗口隐藏准备。显示“正在读取图库索引”和首屏缩略图实际准备数量，不显示虚构百分比。首屏就绪后显示主界面，保留窗口大小/最大化状态。
- 仅准备当前视口，后续媒体继续按需加载，不把整个图库或全部8GB缓存读入内存。首屏图片慢或无法读取时最多等待8秒，随后保留可重试占位并在后台继续。空图库无需等待缩略图。初始化/页面加载失败显示可读原因、重试和退出；关闭加载小窗退出隐藏主窗口，二次启动只聚焦当前加载窗口或主窗口。
- 合并StrictMode导致的重复初始刷新；初始化期间暂存变更通知，成功后补一次刷新，失败不会被后台空状态刷新悄悄覆盖。
- QA专用缓存改为userData/media-cache，避免Windows下与Chromium的Cache目录重名。真实旧缓存与正常新装的软件目录/cache/media规则不改变。复测已有缓存重开时不扫描或改写测试缩略图。
- 常规的导入、缓存、整理、任务、目录五个模块由统一容器控制，板块之间固定20px，不再叠加各组件margin。
- 缓存任务详情补回持久化的来源/目标路径，兼容本轮前已有任务；旧任务payload其实有source，只是通用结果接口未传给UI。完成、取消、迁移中分别显示准确说明。
- 媒体缓存移动最多4个文件并发，旧副本清理最多2个并发。保留不覆盖复制、来源指纹检查与SHA256校验，切换条件不放宽。每32项或约200ms合并进度写事务，不再为每个文件广播图库刷新。每条文件结果仍持久保存。
- 任务详情显示校验后平均速度和预计剩余时间；复制量太小时不展示不稳定估计，清理阶段不冒充复制进度。预计值受磁盘、文件数量和大小分布影响，不保证固定完成时间。
- 移动期间只暂停新的缓存读取/生成/清理请求，图库索引、标签与相册操作仍可使用。切换后等待请求使用新目录；切换前取消/失败恢复原目录，已复制目标保留供重试。提示中说明“新预览暂时等待”。取消等待当前不可中断的文件复制安全结束，提交后不再允许取消。

验证：工程与React严格类型检查、生产构建通过；181项完整自动测试通过。6项启动隔离场景覆盖延迟初始化时主窗隐藏、首屏缓存就绪再显示、最大化恢复、已有缓存不扫描/不改写、失败与重试、空图库、退出无残留隐藏窗口。开发设置回归11项、冻结EXE11项通过，涵盖20px间距、路径显示/迁移与原件保护。QA素材与数据库均独立，未移动真实用户缓存、数据库或原媒体。

证据：output/audit/m2-startup-20261020/tests.json和validation.json；运行包release-m2-20261018.4.8.7/win-unpacked/Lumina.exe。本轮不commit/push。未将其他模块宣称为已完成并行优化，见[批量操作并发审计](performance-concurrency.md)。虚拟机/真实外部接收/十万真实媒体压力仍待验。
