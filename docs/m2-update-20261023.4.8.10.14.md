# M2 .4.8.10.14 足迹复用扫描结果

## 原问题

目录扫描已通过 EXIF 读取 GPS，但原足迹分类任务又逐张调用完整元数据提取，并对所有可见照片重复执行；逐项 setTimeout(0) 在 Windows 上也会累积定时器延迟。已有经纬度、无 GPS 以及已整理的照片未充分复用结果。

## 修改

- 新扫描照片时直接离线匹配附近城市并写入元数据，足迹读取数据库即可展示；不自动创建地点标签/相册，不联网。离线城市树按需建立一次，复用已有索引。
- “整理地理信息”改为“补充地点分类”，用于创建地点标签与智能相册。优先使用已存 GPS；旧库已有宽高/格式等提取结果也复用，不要求重扫目录。确实没有元数据的旧行才补读一次。
- 已确认无 GPS 的照片不加入任务。使用文件指纹、坐标、人工地点及算法版本构成整理键，跳过未变化且已完成的照片；无附近城市结果也保留，避免反复匹配。
- 文件变化时随正常扫描更新 GPS 和自动地点；已移除的 GPS/自动城市清除，人工修正保留。后续分类使用人工地点，不用 GPS 推断覆盖人工分类。
- 地理任务每8项用 setImmediate 让出事件循环，保留暂停/取消检查，移除每张照片的定时等待。公共任务同范围合并仍有效，按钮增加准备状态与重复提交保护。
- 无需处理时直接显示“地点分类已是最新”，不打开空进度窗口。任务明细解释缓存复用与旧行补读行为，足迹提示待处理照片数。
- 撤销仅还原本次自动分类的可撤销部分，扫描已有位置和后续人工修正保留；撤销后允许再次补充分类。

数据库仍为 schema11，无结构迁移。当前是本地测试包，GitHub 已发布版本仍为 .13；未覆盖或重新发布旧版资产。
