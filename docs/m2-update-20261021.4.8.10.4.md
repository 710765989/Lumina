# M2 .4.8.10.4 缓存生成、读取与复用检查

日期：2026-10-21。设计0.8.1、数据库schema10不变。仅处理软件源码及隔离素材，没有迁移、删除或重建真实图库缓存。

## 修复及优化

- 缩略图所有公开生成入口统一复用缓存和同一路径的生成锁；同一媒体在所有界面尺寸下共用640×640以内JPEG。服务请求按媒体及指纹合并，先锁定再异步检查，不再按显示尺寸重复建任务。生成队列中再次确认已有输出。
- 已成功生成的JPEG直接记录为已校验，读取时不再立即完整解码一次；首次读取既有磁盘缓存仍验证完整性，并合并同文件并发检查。校验戳加入ctime和文件身份，缓存变化、删除后不会误用旧结果。过期媒体的生成任务检查当前指纹，避免覆盖有效版本；未删除成功的旧变体仍留在索引，供后续清理重试。
- 照片预览的请求锁提前到stat等异步操作之前；最多同时生成2份大图预览。4096以内的原图不再为屏幕/原尺寸生成两份相同PNG，大原图仍保留用途不同的两种清晰度。刷新和重试先验证已有预览，正常文件不重写，损坏时用完整临时文件原子替换。同一重试URL被多次读取时只处理一次重试标记，仍逐次经过核心媒体授权检查。
- 内存缩略图命中不再排在冷读盘队列后面；保持32MiB编码字节预算、冷读取最多4路和文件变化校验。照片原件和预览改为流式响应，支持范围读取，避免先在主进程整文件分配Buffer。缓存清单同文件并发登记合并；保留持久清单及增量更新，不因浏览重新扫描缓存目录。
- 视频悬停同一媒体的新会话/范围请求复用正在生成的短片，并转交取消所有权；兼容播放继续共用转码与检查点，源指纹变化时不再误用旧的在途请求。已完成视频缓存直接复用。
- 缩略图自动生成失败后对相同指纹退避30秒，最多记录512项，避免滚动或重新挂载触发反复失败；手动重试及任务重试仍可立即执行，成功后解除退避。原文件指纹改变使用新键。
- GIF回归发现布局缩放动画完成时可能没有新的IntersectionObserver事件，导致名额沿用中间位置；增加布局提交和动画结束时的一次合并帧刷新，不增加持续轮询。面积不足一个像素的差异视为同面积，保持从上到下、从左到右的稳定排序。

## 完整检查范围

| 环节 | 检查结论 |
|---|---|
| 缩略图 | Canonical路径、缓存命中、并发生成、损坏修复、指纹变更、过期任务、旧变体清理已检查 |
| 照片预览 | 屏幕/原尺寸、幻灯片预加载、查看器和对比重试、同URL重复请求、读取传输已检查 |
| 视频 | 视频海报、悬停短片、兼容播放、范围请求、关闭暂停及检查点复用已检查 |
| 读取 | 核心缓存校验、主进程编码字节LRU、渲染层版本URL、GIF逐帧读取及释放已检查 |
| 清理和迁移 | 缺失原件索引清理、缩略图与预览删除、无用缓存判定、迁移请求屏障、取消、恢复、增量清单由自动测试覆盖；EXE验证移动后不重新生成 |
| 扫描关系 | 切视图、缩放、关闭/再次打开照片和读取缓存不创建新的扫描任务；缓存目录仍排除在目录监听之外 |

缩略图、照片大图预览、视频短片和兼容视频服务不同用途，不应误认为重复缓存。屏幕预览与原尺寸预览仅在需要不同分辨率时分别保留。本轮没有为GIF新增持久动图缓存，也没有批量预生成整个图库。
