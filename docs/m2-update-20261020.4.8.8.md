# M2 .4.8.8 扫描与缓存读取、迁移进度和交互修复

日期：2026-10-20至21。基于 .4.8.7；设计保持0.8.1。数据库schema升至9以保存缓存清单，升级前自动备份，媒体索引、标签、相册和现用缓存位置保留。

- 缓存迁移分两步：复制并校验、切换后清理旧缓存。界面按各阶段显示独立计数，总进度前半对应复制校验、后半对应清理；结束前最多99%，任务结束才100%。清理阶段计数每32项或200ms持久化，后台通知、常规板块、任务列表及详情统一口径，旧记录兼容。
- 修复 DJI 等部分 MP4 在输入端 seek 到0秒时 ffmpeg 没有输出首帧却成功退出的问题：顺序解码第一视频流，不再执行该 seek；先写临时文件、确认非空可读再原子发布；未输出画面时显示可读原因。只读核对了用户截图对应的 DJI 视频，原逻辑无输出，改后产生26938字节有效JPEG；验证输出只写工作区tmp，没有改原视频或真实缓存。
- 导入设置与确认窗口的复选框、文字垂直居中；长路径消息框内换行；目录预览固定76px容器，播放标识限制在图内，消除覆盖整个窗口的椭圆图标。
- 应用内媒体拖出后回到自身窗口，不显示导入遮罩、不创建导入任务；下一次独立外部拖入仍可用。保留拖出缩略图和外部软件复制能力。隔离验收中的拖放路由为事件模拟，真实Windows第三方接收兼容仍待验。
- 扫描元数据读取全局最多4份并发，其中视频探测最多2份；仅向前准备4项，按原文件顺序写数据库，逐文件结果、指纹复用和重命名检测保留。暂停/取消或目录停用时停止后续派发，在途读取结束后不写入；同目录请求继续合并。不引入JavaScript工作线程，也不限定只能用4核。
- 扫描进度每32项合并更新，界面通知最多约每500ms一次，统计重算间隔延至5秒及批次结束，避免随每30项频繁刷新整个图库。
- 缩略图首次完整校验受全局3槽限制，与生成共享预算，同路径校验请求合并；已校验文件指纹未变时复用结果。主进程缓存最近读取的压缩JPEG字节，上限32MB，LRU淘汰，最多4个文件读取；每次仍由核心核对媒体并解析当前路径，磁盘文件变化、迁移或删除使旧条目失效。磁盘仍只保存一份缩略图。
- 常规顺序调整为图库目录、导入、缓存（含存储分布）、整理与文件设置、任务状态。缓存清单持久保存每份缓存的位置、大小、指纹；生成、删除、迁移增量维护，普通查看和扫描结束后的重汇总读取清单，不反复枚举缓存目录。首次建立或手动“计算索引与缓存”才全量校准软件外变化；手动校准期间的新生成/删除通过版本检查保留。
- 新增“无用缓存”数量/大小和独立清理入口，包含旧指纹、扫描确认缺失及无关联的再生文件。隐藏、停用及回收站中仍有效的文件保留；原媒体、未知文件不作为可清理缓存。执行时重新核对媒体用途、文件指纹及生成状态，支持后台取消/恢复；缓存移动同时重定位清单和暂停清理任务。
- 相册的“导出相册”移至更多菜单首项（列表卡片和详情一致），保留原导出确认。相册路径最多同时显示5级，依据可用宽度显示层级；点击任意祖先直接跳转，较早层级折叠至省略号选择器，长名称省略但保留完整提示。

验证：191项完整自动测试、工程与React严格类型检查、生产构建通过。开发版11项本轮窗口验收及11项缓存设置迁移回归通过；最终EXE本轮11项、拖出15项及缓存迁移11项通过，共37项；证据见output/audit/m2-cache-progress-20261020/validation.json。

性能对照：本机600张生成JPEG、各轮新建隔离SQLite数据库，旧版两轮8.18/5.11秒，新版3.13/3.52秒，通知21次降至8次。仅本机热文件缓存测试，不代表真实17,000/38,000文件、HDD/SSD对照或所有格式的提速比例。证据：output/audit/m2-cache-progress-20261020/scan-benchmark.json。

迁移复制/校验4文件、旧副本清理2文件不改变；后台标签、删除、重复检测等模块没有在本轮全部改成并发。源码与运行包同步feature/M2，不commit/push。真实图库、数据库和缓存均未被本轮修复或测试写入。
