# M2 .4.8.6 缓存位置与常规设置

日期：2026-10-20。基于 .4.8.5；设计仍为0.8.1，数据库schema仍为8。

- 常规下方的“目录设置”整体加白色背景、细边框和统一内边距，添加目录、实时监听、目录统计及各目录操作集中在同一板块。目录列表每页10条；任务流水线仍每页5条。移除目录后自动纠正页码。
- “导入设置”独立背景框；常规与导入确认框中的“不再提示，以后都导入到这个路径下”统一12px。
- 新增“缓存设置”：只显示一个当前实际路径的只读框，右侧“更改缓存目录”打开文件夹选择器，不能手动填写。选好后核对缓存数量、体积和空间，弹出来源/目标与移动确认；取消选择或确认不切换路径。
- 保留现有缓存位置，初始显示实际目录，不因升级自动迁移。仅全新安装且无旧缓存时默认软件目录下的cache/media；QA测试使用隔离目录。路径不可写时报告明确错误，不悄悄切换到其他缓存位置。
- 仅移动缩略图、图片预览、兼容视频；SQLite数据库、原媒体和Chromium的Cache/Code Cache/GPUCache保持原位。缓存位置持久化，后续生成、读取、清理与监听忽略范围随之更新。
- 移动作为一条后台任务，冻结新缓存写入并等待在途生成/清理，复制并逐项SHA256校验，全部成功才切换。切换前失败或取消保持旧目录，已复制目标供重试校验复用；成功后清理已验证旧副本，未知、被修改或占用文件留原处。恢复中任务不会被历史清理误删。
- 目标不得在图库内、包含图库/数据库/原件、与源互相包含或经过链接；目标非空时只允许本库所属缓存。拒绝覆盖不同内容。迁移仅切换前可取消，不提供通用暂停/恢复；失败重新选择目录重试。已暂停的缓存清理任务随路径切换安全重定位。
- 修复迁移完成后UI仍显示旧路径的异步更新问题；目录监听即时反馈，保存其他常规设置不覆盖监听状态。
- 测试临时目录清理增加关闭数据库后的重试；已按授权清理129个旧Lumina测试目录和209个超过一天的空.tmp目录，共约115.7MiB。近期或非空归属不明的.tmp保留。

验证：179项完整自动测试通过（新增7项缓存路径/迁移测试），工程和React严格类型检查及生产构建通过。开发窗口与冻结EXE各9项隔离验收通过，检查单行只读路径、背景框/字号、目录10条分页、监听保存、危险目标拒绝、移动完成后的路径切换、旧缓存复用及原件不变、浏览继续可用。文件选择器在测试中返回隔离目录；未移动真实用户缓存、数据库或图库。

证据：output/audit/m2-cache-settings-20261020/tests.json和validation.json，运行包release-m2-20261018.4.8.6/win-unpacked/Lumina.exe。虚拟机、真实外部软件接收和真实十万媒体压力仍待验；本轮不commit/push。
