# M2 媒体呈现计划

M1 已完成本地媒体的索引和管理。M2 负责把索引内容变成可浏览的媒体界面，按照片、预览、视频三个增量交付。

## M2.1 照片缩略图

- 使用 `sharp` 在 core-host 的媒体 worker 中生成 JPEG 缩略图。
- 缓存目录位于应用 userData，不写入用户图库目录。
- 缓存键由媒体稳定 ID、文件指纹、尺寸和裁切模式组成；文件变化自动生成新缓存。
- `tasks` 表继续记录 thumbnail 任务的排队、处理中、完成和失败状态。
- 失败时保留原媒体索引，桌面端显示统一的无法预览占位。

## M2.2 桌面端预览

- 媒体网格读取缩略图缓存，不在渲染器直接遍历用户目录。
- 点击照片打开详情预览，支持加载中、加载失败和返回图库。
- 通过受控的本地媒体协议向渲染器提供缩略图和原图，避免把任意文件路径暴露给页面。
- 大图库使用分页和虚拟列表，避免一次加载全部媒体。

M2.2 已完成照片链路验证：`lumina-media://thumbnail/<mediaId>` 提供缩略图，`lumina-media://original/<mediaId>` 提供照片原图，桌面端双击媒体卡片打开预览；视频预览由 M2.3 补充完成。

## M2.3 视频

- 使用 `ffmpeg` 或 `ffmpeg-static` 生成视频封面帧。
- 详情页使用受控媒体协议和 HTML5 video 播放，保留无法解码和访问受限状态。
- 视频缩略图和播放任务与照片缩略图共用任务恢复和失败重试模型。

M2.3 已完成：受控媒体协议可以把已索引视频交给 HTML5 video，`ffmpeg-static` 可以抽取视频封面帧并写入缩略图缓存；桌面端提供媒体加载失败占位，任务面板显示失败/暂停状态并支持缩略图重试，应用重启会把中断任务恢复为可处理状态。

M2.4 已完成：应用重启会把运行中的任务转为可恢复状态，缩略图任务保存媒体参数并支持重试；图库和相册媒体网格使用可视区域虚拟列表，只为当前可视媒体生成缩略图；缩略图缓存命中时复用已有文件，不重复生成或创建任务；设置页提供扫描/缩略图任务状态、暂停与失败提示和缩略图重试入口。图库和相册均按 200 条批量从索引加载，批量加载后交由虚拟列表呈现。

M2.1 已完成：`sharp` 可以生成指纹化 JPEG 缩略图，缓存键包含媒体 ID、文件指纹、尺寸和质量，源文件保持不变；M2.3 已使用项目内置的 `ffmpeg-static` 完成视频封面和播放链路验证。M2 的媒体缓存和临时文件必须继续加入 Git 忽略规则，不能进入远程仓库。
